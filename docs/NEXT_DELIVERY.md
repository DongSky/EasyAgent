2026-09-20。用户要求两组功能与 Skills 立即开发；仅集成测试，无 Docker。以下按实际实现更新，不把接口存在写成生产验收完成。

## A：扩展生态与办事能力

- A1：统一技能/扩展的目录、来源预览、安装、版本、更新、停用与导出；固定来源提交，凭证不进入包。
- A2：可替换的模型流、记忆、上下文整理、执行环境、审批通道契约；声明、权限、调用与故障统一。
- A3：浏览器和本机终端执行入口、消息渠道适配与语音输入/输出；复用现有审批、回执和模型协议。
- A4：现成生活任务资源与普通用户界面；插件与 Skills 被自动构建目录发现。
- A5：集成回归、故障恢复、发行构建与长期验证。真实账号、手机真机、正式签名及 72 小时证据独立列示。

Pi 原生 TUI/TypeScript 包兼容、Chord 完整远程复制和分布式多租户不等同于上述通用契约；本期不声称实现这些兼容层。

## B：零代码在线修复与扩展

- B1：目标、完成条件、允许能力和总预算持久化；执行与业务验收分开。
- B2：失败回执/产物驱动有界修复，保存新版与原因，新增可见步骤与子流程。
- B3：检查点续跑、跨版本副作用保护、停滞与预算停止、等待用户与反馈续跑。
- B4：自动扩展纯计算代码经过候选、测试与发布；仍受原始工具/模型/权限边界限制。
- B5：零代码入口与任务页显示目标、改版、证据、暂停/继续和结果反馈。

## C：Skills

- C1：标准 SKILL.md、配套资源、包校验、SQLite 持久不可变版本、导入/导出、停用/回滚。
- C2：远程 GitHub 来源固定提交与预览；内置生活场景目录及可配置来源。
- C3：按需列表/正文/资源工具、会话 /skill、自动构建选取；不由 Skill 授予工具权限。
- C4：Agent 技能候选与发布入口，版本冲突和审批保护；现有经验评估仍独立保留。
- C5：设置中的“使用技巧”界面、三语言 SDK 和集成场景。

执行失败修复、无错误但产物漏项、动态添加节点、停滞停止、预算不重置、用户反馈续跑、跨改版写入不重复、等待审批恢复。
