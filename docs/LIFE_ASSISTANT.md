# 首个 Example：生活事务管家

## 产品目标

把散落的材料和约定，变成一份持续更新、有人负责、可确认完成的安排。首轮验证以搬家为主，提供旅行、学校通知、维修模板以检验框架的可复用性。

主界面展示「今天要做」「正在等谁」「哪里卡住」「已经办完」。项目中保存任务依赖、负责人、截止日期、联系人、资料链接、费用与完成凭证。事项是否完成由用户确认并提供证据，不能仅根据模型的自述标记完成。

## 首版流程

1. 选择场景、输入主要日期，建立带依赖的项目草稿。
2. 可粘贴通知或约定，提交框架的 model 工作流提取候选事项；确认后加入项目。
3. 指派负责人，标记等待对象与阻塞原因；依赖未完成时不能办结后续事项。
4. 日期变化时自动调整尚未完成事项，保留已完成事项和变更记录。
5. 记录凭证后办结；本地提醒以待处理清单持续呈现。

## 明确的 MVP 边界

本地单用户可记录家人分工；这不等于多个账户的实时家庭协作。资料可保存文本/链接；未实现自动邮箱接入、OCR、日历双向同步、商家调用、电话、付款或代办下单。免费/付费拆分属于产品假设，首版不虚构已验证商业化结论。

模型可提取事项，但所有日期、费用和承诺都需要来源与确认。没有 API key 时使用明确标记的场景模板；界面不把模板生成描述成实际模型推理。
