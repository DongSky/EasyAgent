# 持续会话、学习与服务连接

工作室新增「持续对话」「服务连接」「经验与代码」「诊断与维护」。这些页面调用与 Python/JS/Rust SDK 相同的 REST 契约，不在前端另写一套执行器。

## 持续会话

Conversation 保存配置与消息树，Turn 排队，实际执行交给持久 Run。支持跟进、运行中转向、安全边界中断、分支、FTS5 检索、手动摘要和可选自动摘要。原始消息保留，摘要记录来源边界。流式 Chat Completions、Responses、Messages 的真实文本增量进入运行事件；缺少结束标识的断流会失败，不把部分文字冒充完成。预览中的旧模型桥接连接可能只有最终回复，以实际 provider 为准。

界面可创建助手、选择模型和能力，普通需求生成完整流程仍使用原零代码入口。模板来自已启用扩展。新用户不必手写 Manifest，进阶授权（动态委派、运行时开发）保留在工作流/SDK 配置中。

## 学习和记忆

已完成/失败任务 → 模型复盘 → Skill 候选 → 执行评估 → 发布/回滚。来源任务与复盘任务均保留。自动复盘默认关闭；开启时设置模型和每日上限，只处理 metadata.learn_as 标记的流程。它不会自动发布，也不会训练模型权重。

`memory.put/remove/merge` 需要 Agent memory_namespaces 授权并经过写审批。合并要求原始值摘要，过期读/并发覆盖会冲突；保留原记录及来源至 memory_archive。memory.search 对 Agent 也检查命名空间。HTTP 管理 API 是本机操作者权限。后台自动摘要同样默认关闭，避免未经配置就增加模型调用。

## 动态协作

`agents.spawn/send/reply/status/wait/cancel` 使用持久子 Run、邮箱和父子预算。子任务只能使用父级授予的模型/工具；再次委派需要 allow_redelegate 和明确子授权。等待释放 worker，单 worker 也能完成父子协作。取消沿子任务传播；邮件在安全边界写入 checkpoint 并去重。

当前是单个 Hub 的持久协作；不是跨机器分布式调度。动态 Agent、固定多角色节点、子工作流是不同入口，复用同一执行与预算机制。

## 凭证与模型

访问凭证按别名在 SQLite 保存 Fernet 密文；本机解密密钥位于数据库旁 `.secrets.key`，权限 0600。不会通过目录/API返回明文。模型测试成功后保存连接与凭证，重启恢复。导入 API 的凭证引用可以在连接中心保存同名别名，不必配置系统环境变量；已有环境变量仍可用。

这是单用户本机凭证库。能读取数据库和解密密钥的同一系统账户仍有访问权，不等于独立硬件密钥托管或多租户隔离。

## 渠道与投递

内置系统通知、通用 Webhook、Telegram、CalDAV、Slack、Discord、飞书。调用连接器先写审批，再进入持久 outbox；工作流成功表示已入队，送达状态单独查看。连接配置固定版本，投递保存配置快照与稳定 Idempotency-Key。支持明确可幂等服务的重试；中断后的非幂等发送标为 uncertain，不自动重发。

### 系统通知

在「设置 → 模型与服务 → 通知与日历」选择「系统通知（当前设备）」，点击「允许系统通知」，然后保存或「保存并发送测试通知」。无需服务地址和 API Key；连接名称和显示名称提供默认值。保存后产生 `connection.<id>` 工具，接受 `{text, title?}`，编码、画布和零代码助手都使用同一工具及审批机制。设置页发送测试是操作者的直接操作，不新建工作流审批。

接收目标是**绑定浏览器所在设备**，不是运行 Python Hub 的服务器。绑定使用当前站点本地存储的随机标识；换浏览器、端口或清除站点数据后需创建或重新保存连接。已有工作流仍固定原版本的接收目标。浏览器要允许通知，页面需持续打开；关闭页面或系统挂起时保留队列，重新打开后继续领取。浏览器的权限与系统勿扰设置分别生效。

当前使用 Web Notifications + Service Worker；只在 HTTPS 或可信本机地址工作，不缓存页面或存储 API 凭证。桌面系统浏览器可用；Android 浏览器依赖其通知支持及前台运行条件。iOS 通常要求主屏幕 Web App，当前没有完成该安装流程、原生 WebView 通知桥接或后台 Push，因此不承诺 iOS 或应用内浏览器可收取系统通知。不支持时界面明确提示改用支持通知的浏览器。

多标签页在 SQLite 事务中排他领取，每个投递只允许一个 claim。浏览器只有在 `showNotification()` 成功返回后才上报 `submitted`（已提交系统），它不等于看见横幅或已读。权限/提交失败为 `failed`；领取后 35 秒无回执为 `uncertain`，不自动重复弹窗，迟到的同一回执可以核验并修正状态。`queued` 仅表示仍等待浏览器接收。未确认的系统弹窗不能标成 `delivered`。

CalDAV 使用 UTC 日期、稳定 UID、ICS 内容转义和 HTTP/ETag 回执。Telegram 固定官方 API，凭证使用别名；实际服务账户、权限和最终投递仍需用户接入验证。

自定义消息网关：配置 `/v1/gateway/connections`，向 `/v1/gateway/incoming/{id}` 提交 `{event_id,thread,text}`。请求头 `X-EAH-Timestamp` 是 UTC 秒数，`X-EAH-Signature` 是 `HMAC-SHA256(secret, timestamp + '.' + raw_body)` 十六进制。允许 5 分钟窗口；重复事件 ID 不能换正文。线程映射到持久会话，回复经过普通连接器审批。当前不是所有聊天平台的原生机器人适配集合。

## MCP

使用官方 SDK 实现 stdio/Streamable HTTP，持久连接任务、按需发现缓存、远端列表变更后重新校验、断线后下一次请求重连。不会自动重放失败的外部写调用。管理页面可发现能力、逐个声明读写/幂等、刷新连接并查看错误。

远端 OAuth 使用官方 SDK 的 discovery、PKCE、动态客户端注册、刷新和 issuer 绑定；token/client info 加密保存。浏览器回调验证匹配的、未消费 state。当前授权回调面向本机 loopback Hub，手机通过电脑 Hub 的已授权连接调用能力。

## 时区定时

五字段 cron + IANA timezone，支持当地时间与 DST。错过触发合并一次补跑，使用原计划时间作幂等键，避免重启后突发重放。界面提供每天、工作日和每周模板；API 可提交完整表达式。任务成功、通知入队和通知实际送达分别保留。
