# 全新任务如何完成

用户描述目标并上传材料，不需要自己填写工具名和输入输出 schema。例如：“把这张照片自然重打光、压暗背景，保留皮肤纹理，适当提高饱和度。”

系统先检查已有流程、工具和服务连接。已连接且具有已知编辑协议的图像模型，会自动获得图像编辑节点：输入中的图片是上传文件的 artifact ID，执行时才转换为接口需要的 multipart 文件；原图保留，返回的图片存为新的 artifact。接口创建本身不会发起付费生成，实际请求仍遵循运行时的审批规则。

## 先建任务，后补模型

完全没有编排模型时，系统先持久保存需求和附件，并列出编排模型要求，不声称已经理解并生成了完整可执行流程。已有编排模型时，构建结果可以包含 `required_connections` 和流程草稿：例如图片编辑能力必须接收原图并返回成品，而不是只返回图片元数据。

接口参数还未知时，用 `planned_steps` 保存操作意图、分叉与汇合依赖，不虚构 API schema。

草稿保存于 `studio-assistant-drafts`，待接入的目标使用 `pending_<需求标识>`，不进入可运行工作流库，不安装草稿中的代码或接口。对话保持 `waiting_connections`，不当作完成或失败。用户接入服务并返回原对话时，`resume-connections` 检查连接变化，再将原始需求、草稿和新的能力目录交给构建器；编译验证通过后执行。占位目标不能直接替换成任意模型来绕过接口验证。

等待状态与附件跨重启保留。继续操作幂等；并发点击不会创建重复任务。没有连接变化时不重新调用模型。后续消息继承原材料并替代等待中的请求，停止操作阻止自动继续。此机制同样支持缺少搜索、语音、视频或自定义接口的任务。

## 缺少节点时

自动构建器可以做三件事：

1. **写计算代码。** 生成新的 JavaScript 节点和输入输出约定。例如解析 CSV、按客户汇总金额、去重、转换数据。实现先在隔离运行器中测试；另一次模型调用只看需求和接口，不看实现，生成普通输入及边界输入的独立测试。测试失败时，把输入、预期值、实际输出及运行错误交给模型，继续修正并重新执行测试；修正实现不能修改独立测试和输入输出约定。测试生成的 JSON 格式有误时先修正格式，不把它误判为代码错误。
2. **找接口并写适配器。** 构建器可以请求搜索，优先使用已连接的搜索工具，未配置时尝试公共网页搜索；读取找到的文档后，自己生成 HTTP 节点及文件参数映射。已有服务的凭证仅能绑定到原服务地址；凭证不进入模型上下文。新服务需要登录或密钥时，说明具体缺少的授权，而不是要求用户提供 schema。
3. **使用本机工具。** 已启用的终端和浏览器操作会进入可用能力目录。构建器可以把脚本与检查命令编排为可见步骤，使用配置的工作目录和站点。纯代码节点本身没有网络、文件系统或宿主权限；需要这些能力的操作应使用对应工具。

新节点通过验证后才注册，并保存为节点库中的一个独立节点。它可以在内部执行多段计算，但对外只有一个输入输出约定，不伪装成子工作流。独立步骤的依赖、分支、多个输入和汇合仍由工作流表达。

## 执行、修正和复用

新建的对话任务执行失败时，系统把错误和已观察到的输出交回构建器，继续修正和验证，直到完成、用户停止或确实需要外部信息。已完成的写操作使用原回执继续，不重复提交；无法确定外部操作是否完成时，保留待核对状态。

通过测试的代码、测试报告、接口约定和使用说明会分别持久化。使用说明保存为 Skill；实现保存为扩展工具和独立节点；整项任务保存为工作流。下一次可以直接匹配已有工作流，也可以在新工作流中复用节点。测试报告只证明实际执行过的用例，不代表所有输入都正确。

所有开发记录保存在当前工作区数据库中。搜索失败、依赖不具备、服务拒绝请求或用户主动设置的额度耗尽时，会保留具体阶段和原因，不伪造成功结果。公共搜索不保证可用；经常联网的任务建议配置 TinyFish 或其他搜索服务。

## 实现与验证

自动纠错覆盖代码测试、HTTP 适配器和工作流校验。接口定义或节点输入不合规时，把实际错误和当前草稿交回模型，逐项修改后重新验证；不会把“校验工具执行完，但返回错误”当作任务完成。旧版留下的这类记录也可从失败处重试：保留原草稿、搜索资料和已完成步骤，只使内部校验缓存失效，不重放外部写操作。

模型单次输出截断时，构建器会切换到分段草稿：每轮提交少量完整的字段、步骤或代码片段，持久保存后再生成下一段。截断的段不会应用，网络失败后继续使用已保存的草稿。整个对象通过 schema、流程和代码测试后才发布，分叉与多个输入不变。构建和纠错不再设置默认的总调用次数、分段轮数、总输出额度或整段构建时限；用户明确设置的限制仍然生效。使用量照常记录，停止操作可以中断运行。普通工具 Agent 也会把输出截断反馈给模型，要求缩小调用继续处理，残缺参数绝不执行。

旧版系统自动生成的两阶段构建任务，在重试时移除之前系统添加的 8/24 次调用和 65,536 tokens 上限，同时保留草稿、回执与使用记录；用户自行定义的工作流限制不会被修改。构建模块在服务启动时一并加载，内部拼装接口兼容旧调用方式，更新应用后应重启服务以载入一致版本。

Agent 上下文默认自动识别，不再固定为 64,000 字符。系统读取当前服务 `/models/{id}` 或 `/models` 中的上下文、输入及输出上限；缓存与具体连接、模型绑定，切换模型重新读取。服务没有返回上限时界面标为未知，不根据模型名称猜测，也不发送付费的长提示探测。实际输入 usage 用于校准长度估计；服务明确报上下文超限时记录可确认的上限，并压缩历史后继续。压缩保留原始要求与完整工具调用/结果组，无法在保留必要材料的条件下容纳请求时停止并保留进度。`context_chars` 仅保留为 SDK 调用方可选的额外约束，默认 `null`，不是模型窗口。

2026-09-21 核对 [Pi agent loop](https://github.com/earendil-works/pi/blob/3390bd93630965a12a0a1a5c36ce890ec22f7e1d/packages/agent/src/agent-loop.ts) 与 [session recovery](https://github.com/earendil-works/pi/blob/3390bd93630965a12a0a1a5c36ce890ec22f7e1d/packages/coding-agent/src/core/agent-session.ts)：它会把工具结果回送下一轮，拒绝执行因 `length` 截断的工具调用，并区分瞬时错误重试和上下文压缩恢复。并非任意截断都自动无损续写。这里按本项目的持久化流程实现同类恢复原则；分段草稿是 EasyAgent 的实现，未复制 Pi 源码，也不声称两者功能等价。

- `assistant_builder.py`：向模型提供现有能力、编译扩展草案和可见工作流。
- `build_capabilities.py`：绑定已有媒体接口、独立测试、修正代码、创建节点及 Skill。
- `build_recovery.py`、`model_limits.py`：分段草稿恢复、服务窗口识别与运行中校准。
- `capability_research.py`：有界搜索与公开文档读取；外部内容只作为不可信参考。
- `workspace_chat.py`：把构建、执行、失败修正和继续执行连接到对话入口。
- `tests/integration/test_autonomous_build.py`：真实 HTTP 和隔离 JavaScript 执行的协议测试，包含修图文件传递、错误实现被测试捕获、重启复用、搜索适配和避免重复写入。测试使用明确的模型夹具，不把它们称为真实模型效果测试。

实现参考了 [Hermes 的技能创建流程](https://github.com/NousResearch/hermes-agent/blob/main/agent/learn_prompt.py)、[技能管理工具](https://github.com/NousResearch/hermes-agent/blob/main/tools/skill_manager_tool.py)和[网页工具](https://github.com/NousResearch/hermes-agent/blob/main/tools/web_tools.py)的组织方式：工具发现、执行验证、保存过程经验。EasyAgent 的实现复用自身的持久化运行器，没有复制这些源码。
