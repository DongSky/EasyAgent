# 目标执行与自动修复

2026-09-20。零代码创建页面可启用“自动检查结果，修复或补充步骤后继续”，并设置最多修改次数及是否允许新增纯计算代码。运行页显示原目标、修订原因、每轮检查结果和当前流程；可补充反馈、暂停续跑、继续，并打开保存的可复用版本。

## 执行模型

一个持久根任务管理不可变的子工作流。每轮按“执行 → 检查 → 修订/扩展 → 验证”推进，出错与产物不符合目标均可触发修订。每个执行版本保存到 `goal_<run_id>.plan`，可以在已保存流程中打开、编辑、导出完整包或作为子流程复用。旧运行与输出保持可追溯。

`GoalSpec` 固定 `objective`、`workflow`、`model`、`checks`、`semantic_check`、`max_revisions`、`allowed_tools`、`allowed_models`、`allow_code` 和 `limits`。修复模型无权改写这些条件。每条 `checks` 包含 `description`、`path`、`schema`，例如 `answer.difference` 必须符合 `{"const":50}`。路径从“步骤 ID → 输出字段”开始。

固定断言先检查实际输出；可选的语义模型只在步骤成功且固定条件通过后审阅目标。零代码界面默认采用语义检查，严格业务检查可通过 API 配置。语义判断存在误差，不能替代外部回执、确定性检查或用户满意度。

所有子执行、验证与修复共用根任务模型/工具/子任务/时间等预算。最多 12 次修订；重复方案、预算耗尽或模型明确停止均返回未完成，根任务失败，不伪报成功。缺少信息进入持久等待，用户反馈承接同一预算。模型不能增加管理工具、嵌套控制器或隐藏工具 Agent 来绕过可见工作流。

## 新代码与副作用

允许新代码时，修复器可提交 JS/WASM 纯计算候选，走已有包校验、真实执行场景和发布链路，然后在新流程中以可见节点调用。候选自己生成的测试不能代替原目标断言。新节点可跨工作流复用、导出分享；完整 Python/Node/Rust 进程依旧走受信任扩展安装路径。

已确认的顶层写操作只有在输入、版本、步骤定义与依赖定义未变时才复用回执，避免修订导致重复发送/预约。可复用的库版本会保留原操作；新任务需执行自己的写入并走审批。变更已完成写入、嵌套写入或结果不确定时，等待核验，不盲目重放。纯读取可在修订中重新执行。

暂停是“暂停后续续跑”；已启动步骤可以完成。控制操作与正在认领的轮次冲突时返回 409，待当前轮结束重试。取消后的根任务不能恢复，已发生的外部操作也不会因回滚流程而撤销。

## API 与验证

- `POST /v1/goals` 提交 `GoalSpec`，返回持久任务 ID。
- `GET /v1/goals/{id}` 返回 run、state、result；通用运行事件流包含 `goal.execution/verified/revised/needs_input`。
- `POST /v1/goals/{id}/control`：`action` 为 `pause`、`resume`、`feedback`，可带 `feedback`。
- 导出保存的执行方案，不直接分享控制器、运行历史或回执。

`tests/integration/test_goals.py` 覆盖产物漏项、工具错误、代码扩展、停滞/越权、确认写入只执行一次、另一个新项目重新执行、重启输入恢复、最终验收提交后崩溃恢复，以及 HTTP 控制入口。

`examples/demos/live_goal_repair.py` 是真实模型的快速验收：初始搬家报价缺少比较结果，要求补齐差价 50 HKD、币种、建议和两份报价；不能仅凭步骤返回成功结束。此案例已实际通过，不等于通用长程任务成功率或 72 小时稳定性验证。
