# 研发计划

基线日期：2026-09-19。每一阶段先明确契约，再实现，再运行集成场景；文档随交付更新。

## 首要验收标准：小白可以自己做

用户进一步明确：代码、低代码、零代码三种方式均需交付。完整性审计后增加 [G1–G6 补齐关卡](COMPLETENESS.md)，原 P5 初次通过只代表基础链路，P6 应用开发必须等待新增关卡。

根据用户补充，默认入口调整为可视化 Studio，而不是 SDK。技术能力必须服务于易用性。

- 从首页选择模板或描述需求，由已连接模型自动选择已接入能力，生成可见、可运行、可导出的工作流，不要求勾选工具与技能或编写 Python/JSON。
- 零 API key 可使用明确标记的本地演示模式；真实模型连接表单提供可理解的配置字段和连接测试。
- 一键试运行，显示正在处理、需要确认、出错原因、完成结果；错误提供具体下一步。
- 保存助手并重复运行；导出同一工作流、输入、依赖说明和 Python/JS/Rust 运行入口，供进阶修改。
- 工具/模型/插件等高级概念收进高级入口；平台机制不塞进生活管家用户流程。
- 验收：浏览器完整创建一个自定义助手、运行、观察结果、保存与导出；另验证失败和审批流程。
- 最新要求：在三入口验收之后，修正零代码手动选能力、模型弹窗和空工作流问题。自然语言编译已进入助手构建主路径，旧的独立 generation 草稿路由仍不开放。
- 可视编排须支持 ComfyUI 式拖动节点与端口连线，自动编译为同一份 Workflow 依赖和参数引用；已增加类型/循环检查、缩放平移、断线、撤销重做与布局保存。
- 这证明产品具备无代码创建流程；是否真正适合小白仍需 5–8 位未接触框架的用户做可用性测试。

## P0 — 需求与契约

- 交付架构、协议、模型边界、运行手册、测试矩阵、首个应用说明。
- 将核心类型固定为 Workflow、Step、Run、Event、Tool、ModelRequest、Skill、PolicyVersion。
- 默认单用户本地部署，macOS/Linux/Windows 兼容设计；公网多租户属于后续产品化阶段。
- 验收：每个功能有接口入口、权限边界、故障行为和可执行验收场景。

## P1 — 持久化运行内核

- SQLite WAL、数据库迁移版本、事务提交、DAG 校验、参数引用。
- 并发 worker、租约与 fencing、心跳、超时、指数退避、取消、延时调度。
- 任务与事件可查询；进程重启恢复；审批暂停不占 worker。
- 外部副作用的幂等键与执行记录；结果不确定时暂停，禁止盲目重复。
- 验收：重启、并发抢占、重试、依赖失败、取消和审批的真实数据库集成测试。

## P2 — Agent 与模型层

- 有界 observe → decide → act 循环，可检查的消息与工具结果 checkpoint。
- 模型请求覆盖 chat、结构化 decision、image、embedding；配置绑定模型别名和能力。
- OpenAI Responses、OpenAI-compatible Chat/Images/Embeddings、Anthropic Messages、本地 mock。
- 显式工具 allowlist、JSON Schema 输入输出校验、模型调用超时与调用/输出预算。
- Skills 渐进加载，普通记忆持久化，带来源的检索接口。
- 验收：通过本地 HTTP 协议夹具验证适配器；mock 只证明编排，不证明模型质量。

## P3 — 互操作与扩展

- Python、JS、Rust SDK 走同一 v1 API；三种语言插件运行真实子进程。
- 插件 manifest 版本、输入输出 schema、环境变量白名单、超时、输出限制。
- 使用官方 Python MCP SDK 接入 stdio 与 Streamable HTTP；通过 MCP 暴露 Hub 功能。
- 插件、模型、工具均由部署者注册，模型不能自行提升权限或安装组件。
- 验收：三语言往返调用、MCP 握手/发现/调用、Skill 验证及权限拒绝。

## P4 — 可控自进化

- 策略包括提示词、模型别名与允许的工具；创建候选、执行评估集、记录质量分数。
- 阈值和基线比较由程序计算，不接受调用者直接上报“通过”。
- 人工批准后激活；后续 run 固定策略快照；保留历史并支持回滚。
- 验收：低质量候选被阻止、未评估候选不可上线、上线/回滚及版本快照测试。

## P5 — 框架功能 demo 与集成关卡

- 增加可视化 Studio：模板、表单创建、模型连接、试运行、状态解释、保存/导出。
- 一条命令运行 DAG/决策/工具循环/图片/向量/插件/MCP/Skills/记忆/审批/恢复/自进化场景。
- 启动真实 HTTP 服务；三个 SDK 与三种插件实际执行，不仅编译。
- CI 配置 macOS、Linux、Windows；本机通过不等于其他平台已经验证。
- 完成框架关卡之后再进入应用开发。

## P6 — 首个应用：生活事务管家

- 四类项目模板：搬家、旅行、学校通知、维修；搬家作为主流程。
- 消息整理 → 草稿 → 确认安排 → 指派/等待 → 阻塞 → 完成凭证。
- 同一界面展示今天、等谁、阻塞、已办完；调整主日期时联动尚未完成的事项。
- 保存原始材料、联系人、文档引用、费用和变更记录；提醒为可查询的本地提醒。
- 浏览器 UI 和 API；模型提取通过框架工作流进行；未配置真实模型时明确使用模板。
- 验收：创建四类项目、改期、依赖约束、家庭分工、完成证据、重启持久化的端到端集成场景。

## P7 — 产品化前的后续关卡

这些是明确的后续研发工作，不作为 0.1 已完成能力宣传：

- PostgreSQL/分布式队列/远程 worker、租户隔离、OIDC/RBAC、加密与保留策略。
- 无 Docker 的受控 JS/WASM、OS 原生隔离或虚拟机运行器；当前子进程不是安全沙箱。
- A2A 全协议互通、语音/视频实时流、训练权重或强化学习式自进化。
- 日历/邮件/消息/OCR/支付真实连接器，时区夏令时重复提醒，可靠外部通知。
- 72 小时 soak、故障注入、备份恢复演练、容量和 SLO 基线。
- 小规模真实搬家项目试用，衡量遗漏率、办结率、介入次数和复用/付费意愿。

- [ ] R4 Agent 代码开发闭环：编写源码和集成场景、试跑、有界修复、验证后按授权发布；在两个业务工作流复用同一版本。

## 移动端优先约束（用户追加）

Docker 不纳入后续设计。Android/iOS 兼容需要运行内核、代码执行政策和后台生命周期三个层面，不能仅靠内置 Python 或已有 Rust SDK。

按 [移动端策略](MOBILE_RUNTIME_STRATEGY.md) 的 M1–M7 推进：共享契约 → Rust Core → Android 本地闭环 → iOS 本地闭环 → 无 Docker 的代码执行 → 可选个人电脑/服务器执行 → 真机及发行验证。上述移动端模块均未完成，不计入当前桌面集成测试通过数量。
